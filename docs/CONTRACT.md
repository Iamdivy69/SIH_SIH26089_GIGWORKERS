## 1. What this app is

**Sahyog** — a cooperative gig services platform for household & community services (SIH26089). Three role experiences in one SPA: **Customer** (Ananya Deshpande), **Worker/member-owner** (Priya Sharma, electrician), **Cooperative admin** (Kiran Rao). It must feel like a mature enterprise product — think fintech operations software, not a startup landing page.

The product's differentiators that MUST be visible in every relevant screen:
- **Explainable matching** — never "AI recommended"; always show score factors + reasons.
- **Transparent finance** — every price/earning is a full breakdown; use the shared pricing components.
- **Worker welfare** — benefits portal quality, contributions traceable to bookings.
- **Cooperative governance** — real proposal voting, one member one vote.
- **Demo data everywhere** — no empty states on primary screens (empty states only for filtered lists etc.).

## 2. Hard rules

1. **You own ONLY your role folder**: `src/components/customer/**` (Task 2-a), `src/components/worker/**` (Task 2-b), `src/components/admin/**` (Task 2-c). You may CREATE files there freely. You may NOT modify ANY file outside your folder. If something is missing in shared code, build a local component inside your folder instead.
2. **Do not add page routes.** The whole app lives in `src/app/page.tsx` via the hash router. Screens are components rendered by your `<RoleApp route={route} />` switch (file already exists with stubs — replace its content, keep the export name and signature).
3. **Route names are frozen** (see §5) — the sidebar/mobile nav reference them.
4. TypeScript strict. No `any` in new code. All data access through the hooks in `src/hooks/use-api.ts` — never `fetch` directly.
5. `bun run lint` must pass with zero errors/warnings in your files before you finish.
6. Design language (STRICT):
   - Light theme, warm paper background. **Primary = deep green.** NO blue/purple, NO gradients, NO glow, NO glassmorphism, NO giant icons, NO decorative shapes.
   - Cards: `rounded-lg border bg-card` (no shadows). Section padding `p-5`. Gaps `gap-4`/`gap-6`.
   - Typography: page title `text-2xl font-semibold tracking-tight`; section heading `text-[15px] font-semibold`; body `text-sm` (14px); secondary `text-[13px] text-muted-foreground`; metadata `text-xs`; table text `text-[13px]`; micro-labels via `.micro-label` class; ALL numbers/amounts get `.tnum` (or use `money()`).
   - Buttons: shadcn `Button` — `size="sm"` for table/inline actions, default size for primary CTAs. Ghost for tertiary.
   - Icons: lucide, 14–18px, `strokeWidth={1.9}`, used sparingly and semantically.
   - Color = meaning only: green=positive/done, amber=pending/attention, red=critical, slate=informational, primary=interactive.
   - Every interactive element: real hover/focus states, keyboard accessible, `aria-label` where icon-only.
   - Responsive: mobile-first valid at 375px; desktop 1280–1440 is the screenshot target. Tables use the `DataTable` component (with `mobileCard`/`MobileRows` where the table is the primary content). No horizontal page overflow.
   - Loading: `LoadingPanel`/`LoadingGrid`/Skeleton while queries load. Errors: `ErrorState`. Empty (filtered) lists: `EmptyState` with a next-step action.
   - Feedback: `toast` from `sonner` on every mutation (already wired in most hooks — don't double-toast; hooks already toast, so only add toasts for local UI actions).
7. **Never** claim real integrations. Verification/insurance/payouts are "simulated" — the header already shows a "Demo · simulated data" badge; you may add small "(simulated)" notes in fine print where relevant.

## 3. How to navigate (router)

```tsx
import { useAppStore } from "@/store/app-store";
const navigate = useAppStore((s) => s.navigate);
navigate("customer-worker", { workerId: "w-priya" });   // → hash #/customer-worker/w-priya
navigate("customer-bookings");
```
Your `<RoleApp route={route} />` receives `route: { name: string; params: Record<string,string> }`. Switch on `route.name`, read `route.params.bookingId` etc. Use `key={route.params.id}` on screen components when re-mounting matters.
